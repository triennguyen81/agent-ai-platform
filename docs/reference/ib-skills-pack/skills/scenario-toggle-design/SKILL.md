# Scenario Toggle Design

## When to use
Use this when the model must tell more than one story and you need cases to switch consistently from a single control rather than by hand-editing inputs. It keeps scenarios coherent and auditable and lets you compare outcomes side by side for a memo or committee.

## Instructions
1. Define the base, upside, and downside cases and the assumptions that differ across them.
2. Build a scenario control that switches all linked inputs from one toggle.
3. Verify each case flows through every statement and output without manual edits.
4. Assemble an output-comparison view across the three cases.
5. Write a one-line narrative explaining what each case assumes and what would trigger it.

## Example prompts
- "Add a base/upside/downside toggle that drives the whole model."
- "Build a scenario manager and compare enterprise value across the three cases."

## Output
A scenario framework with case definitions, a single toggle, a side-by-side output comparison, and a short narrative per case.
